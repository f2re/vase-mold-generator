# Vase Mold Generator

Локальный веб-генератор печатной опалубки для цилиндрической вазы. Размеры → осмотр сборки → STL. Версия 0.2.0.

3D-просмотр и экспорт используют **одни и те же треугольные сетки**. Изменение размеров перестраивает оснастку, список деталей, расчёт силикона и проверку области печати. Во время пересчёта или ошибки размеров выгрузка старого STL заблокирована.

## Запуск

Нужны Python 3.9+ и современный браузер. Node.js нужен только для тестов и командного экспорта, не для работы интерфейса. Нет npm-зависимостей, CDN, внешних шрифтов, серверной обработки моделей и Docker.

```bash
git clone https://github.com/f2re/vase-mold-generator.git
cd vase-mold-generator
python3 serve.py
```

Откроется `http://127.0.0.1:8765`. На macOS можно запустить `bash start.command`, на Windows — `start.bat` после установки Python. Другой порт: `python3 serve.py --port 8766`. Остановка: Ctrl+C. Сервер слушает только loopback. Через `file://` приложение не запускается: браузеру нужен HTTP для модулей и Worker.

## Работа с моделью

Слева задаются размеры вазы, зазоры под силикон и параметры принтера. В центре находится модель. Справа — детали, их видимость, размеры и выгрузка выбранного элемента.

| Режим | Назначение |
|---|---|
| Сборка | Проверить взаимное положение элементов |
| Разнесение | Раздвинуть детали ползунком, увидеть втулку, плашку и дно |
| Разрез | Посмотреть внутренние зазоры; разрез только визуальный, STL не меняется |
| Раскладка | Рассмотреть все печатные детали отдельно; это не автоматическая раскладка по столам |

Перетаскивание вращает, колесо масштабирует, Shift + перетаскивание или правая кнопка перемещает. Касание поддерживает вращение, два пальца — масштаб. Нажатие выбирает деталь; справа доступны «Только эта» и STL. Стрелки вращают модель с клавиатуры, +/− масштабируют, F вписывает, Escape снимает выбор. Пробы защёлки и контрольные модели доступны в списке, но скрыты при открытии.

«Скачать STL» сохраняет ZIP рабочего комплекта: отдельные STL, параметры JSON, размеры и координаты сборки в manifest.json. Пробная пара выгружается отдельно. «Сохранить проект» и «Открыть» работают с JSON, не с произвольными STL. Снимок сохраняет текущее изображение PNG.

## Что генерируется

Для исходной вазы Ø150 / Ø100 × 270 мм, дна вазы 10 мм и силикона 10 мм:

- наружная опалубка Ø176 мм: два яруса по 137,5 мм, по две половины;
- основание и широкая верхняя плашка с четырьмя окнами;
- полая втулка Ø80 мм, две секции с внутренним соединительным пояском;
- **глухое защёлкивающееся дно** и отдельная крышка полости втулки;
- пробная пара защёлки, контрольная ваза и два объёма силикона.

Всего 10 рабочих печатных деталей, 2 пробы и 3 контрольные модели. Расчётный объём силикона около **2,23 л** с перемычкой 5 мм над кромкой, без технологического запаса. При области 180 × 180 × 180 мм и заданных полях все рабочие детали помещаются. Для других размеров программа проверяет каждую деталь; чрезмерно крупные детали не выдаются за подходящие.

## Технология и ограничения

Это **опытная оснастка**, не проверенная физической заливкой. Сначала напечатайте пробную пару защёлки. Кожух имеет простые стыки: нужны наружные стяжки и герметизация. Посадка и герметичность зависят от PETG, профиля и принтера.

Двухэтапная схема: сначала наружный силикон до кромки вазы, затем предварительное заполнение внутреннего дна, медленное погружение глухой втулки с наклоном, фиксация плашки и доливка через её окна. Это не гарантия отсутствия пузырей: совместимость слоёв и режим отверждения выбираются по документации конкретного силикона. Гипс, разделитель и силикон здесь не моделируются физически. После изготовления форма используется перевёрнутой, с заливкой гипса со стороны исходного наружного дна вазы.

Подробности: [геометрия и сборка](docs/ENGINEERING.md), [проверки](VALIDATION.md).

Поддерживаются только параметрические цилиндрические вазы. Нет импорта произвольного STL, офсета сложных поверхностей, анализа поднутрений, 3MF и слайсера. Визуальный разрез не закрывает сечения крышками. WebGL имеет резервный 3D-режим на Canvas2D; в текущей среде проверен именно резервный режим.

## Разработка

```bash
npm test
npm run example
# Для браузерных проверок, отдельно от пользовательского запуска:
python3 -m pip install playwright
python3 -m playwright install chromium
VMG_SCREENSHOT_DIR=artifacts python3 tests/browser_test.py
```

`output/` содержит пример STL и ZIP; файлы не включаются в Git. Для проверки через реальный локальный сервер задайте `VMG_TEST_URL=http://127.0.0.1:8765`. Без этой переменной тест загружает те же исходники через Blob-модули, что позволяет проверять интерфейс без сети. GitHub Actions запускает тесты; результаты удалённого CI следует смотреть отдельно от локальных результатов.

## Правила для агентов

[AGENTS.md](AGENTS.md) задаёт обязательную последовательность: Impeccable → выбор направления Taste → реализация по Impeccable → движения Emil Kowalski → финальная проверка. Контекст находится в [PRODUCT.md](PRODUCT.md), принятый дизайн — в [DESIGN.md](DESIGN.md), источники и ограничения применения — в [SOURCES.md](SOURCES.md).

```bash
python3 scripts/install-skills.py
```

Установка скиллов — необязательный шаг **для разработчика**, которому нужны Git и доступ к GitHub. Версии закреплены SHA в skills.lock.json. Скрипт сохраняет полные upstream-репозитории с лицензиями и создаёт локальные ссылки; код скиллов и хуки автоматически не выполняет. В обычном запуске приложения они не участвуют. На Windows создание символических ссылок может потребовать соответствующих прав.
