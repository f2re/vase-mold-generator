## Что строится

| Источник и режим | Результат |
|---|---|
| Ваза по размерам | Кожух, основание, полая втулка с глухим защёлкивающимся дном, широкая верхняя плашка |
| STL → опалубка для силикона | Основание и разъёмные стенки по выпуклому контуру или прямоугольнику |
| STL → жёсткий негатив | Две половины с вычтенной полостью, установочными штифтами, литником и отдушинами |

Опалубка удерживает силикон вокруг мастера; негатив сам является жёсткой формой. Это разные технологии. Для полых и зацепляющихся деталей нельзя считать разборность автоматически решённой.

## Запуск

Нужен **Python 3.9+**. Для булевых операций со STL установите [OpenSCAD](https://openscad.org/downloads.html). Дополнительные Python-библиотеки, Docker и npm-пакеты пользователю не нужны. Параметрическая ваза и предпросмотр своего STL доступны без OpenSCAD.

```bash
git clone https://github.com/f2re/vase-mold-generator.git
cd vase-mold-generator
python3 serve.py
```

Откроется `http://127.0.0.1:8765`. На Mac: `bash start.command`; Windows: `start.bat`. Другой порт: `python3 serve.py --port 8766`. Через `file://` приложение не запускается. OpenSCAD ищется в PATH и стандартной папке приложений; нестандартный путь задаётся переменной `VMG_OPENSCAD`.

## Рабочий процесс

Выберите источник. Для STL загрузите файл или откройте пример, проверьте единицы, масштаб и повороты. Настройте тип оснастки и детализацию. В STL-режиме нажмите **«Построить форму»**; ваза пересчитывается при вводе размеров. Расчёт можно отменить.

Просмотрите сборку, разнесите детали ползунком, включите разрез или рёбра сетки. Выбирайте детали в 3D или списке справа, скрывайте мешающие, скачивайте отдельный STL. Для негатива точки литника и отдушин выбираются на поверхности; каналы направлены вверх по Z.

**«Скачать STL»** сохраняет ZIP рабочих деталей и манифест сборки. **«Сохранить»** в STL-режиме сохраняет JSON с исходной сеткой и параметрами уже из валидного предпросмотра, до CSG. Импорт проекта атомарен: ошибочный файл не меняет текущую модель. Изменение параметров блокирует устаревший экспорт.

Просмотр и STL используют одни треугольники. Разнесение и визуальный разрез не изменяют экспорт. «Все детали» — обзор, не раскладка по столам. Управление: перетаскивание — вращение, колесо — масштаб, Shift/правая кнопка — сдвиг; стрелки и +/− работают с клавиатуры, F вписывает, Escape отменяет выбор точки.

## Детализация и точность

Профили новых дуг: **0,10 / 0,03 / 0,01 мм**, своё отклонение **0,005–0,2 мм**. Число сегментов зависит от радиуса и отклонения хорды; ручные сегменты вазы и старые JSON сохранены. Это точность геометрической аппроксимации, не принтера. Увеличение детализации **не восстанавливает кривизну грубого исходного STL**.

У выбранной детали видны треугольники, оболочки и состояние численной проверки. Для вазы показаны аналитический и сеточный объёмы силикона. CSG-результат проверяется на дефектные рёбра и вершины, дубли, вырожденные грани, отдельные оболочки и численные пересечения. Неполная проверка не считается успехом. Подробные измерения и границы алгоритма — [в отчёте аудита](docs/AUDIT-0.3.1.md).

## Ограничения

STL: до **15 МиБ / 100 000 треугольников**. Для негатива нужна одна замкнутая ориентированная оболочка. Численная BVH-проверка имеет допуск и лимит ресурса; это не точные геометрические предикаты и не гарантия извлечения. Самопересечения и дыры не ремонтируются автоматически.

Контур опалубки — выпуклая проекция, не равномерный 3D-офсет. Мастер касается основания; силикона под его опорной поверхностью нет. Автоматические внутренние сердечники произвольного STL, выбор оптимального разъёма, 3MF, слайсер и раскладка по столам не реализованы. Большие основания и половины негатива не дробятся автоматически; превышение области печати блокирует комплект.

**Физическая печать и заливка не проверены.** Нужны пробы посадок, герметичности, вентиляции и разборки. Рёбра просмотра ограничены 50 тысячами линий; сетки экспорта не обрезаются. Локально проверена CPU-отрисовка, не аппаратный WebGL.

## Проверки и разработка

Пройдено **154 проверки**: 41 JavaScript, 49 Python/CSG/API, 64 браузерных сценария. Условия и непроверенные области указаны в [VALIDATION.md](VALIDATION.md). CI повторяет HTTP-сценарии и выпускает новую версию только после успешных тестов.

```bash
python3 scripts/make-examples.py
npm test
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm run example
python3 -m pip install playwright==1.57.0
python3 -m playwright install chromium
python3 serve.py --no-browser
# В другом терминале:
VMG_TEST_URL=http://127.0.0.1:8765 python3 tests/browser_test.py
VMG_TEST_URL=http://127.0.0.1:8765 python3 tests/browser_stl_test.py
VMG_TEST_URL=http://127.0.0.1:8765 python3 tests/browser_audit_test.py
```

Node.js и Playwright нужны разработчику, не пользователю. `scripts/build-release.py` создаёт исходники, примеры оснастки, снимки и SHA256SUMS. Локальный сервер проверяет Host/Origin и токен сессии; пользовательский SCAD не исполняется. Не публикуйте сервер в интернете — [SECURITY.md](SECURITY.md).

[AGENTS.md](AGENTS.md) сохраняет порядок Impeccable → Taste по назначению → Impeccable → Emil Kowalski → финальная проверка. Направление интерфейса — [DESIGN.md](DESIGN.md), роли — [`.agents/roles/`](.agents/roles/). Upstream CLI и отдельные ИИ-субагенты при этом аудите не запускались.
